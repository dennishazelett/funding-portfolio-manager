# Funding Portfolio Model

Use this as a structural model, not mandatory boilerplate. Preserve the user's established structure when it already works.

## 1. Strategic objective

State the coherent research program and explain how disease- or domain-centered arms remain independently fundable while sharing infrastructure or scientific principles.

### Portfolio maintenance rule

State that the document is current-state, not a historical log. Retain active applications through final disposition; retire completed tasks and obsolete opportunities.

## 2. Portfolio design principles

Recommended subsections:

- Maintain scientific distinctness
- Use submission limits/cycles strategically
- Favor reviewable, repairable applications
- Protect against overlap
- Route programs to the most scientifically natural funding home

Useful distinctness test:

> Each grant should still make sense as an independent application if the other portfolio programs disappeared entirely.

Compare applications across:

- central scientific question
- disease/domain biology
- cohort/data-generation strategy
- hypotheses
- validation plan
- collaborators
- endpoints/benchmarks
- biological interpretation
- translational significance
- methodological deliverables

## 3. Current sponsor pipeline

Create one subsection per active or concretely planned application.

Suggested fields:

- Mechanism
- Program/application
- Collaborator(s), when relevant
- Status
- Scientific emphasis or strategic fit
- Current state
- Unresolved dependencies
- Next action

Do not keep terminally retired concepts here.

## 4. Foundation and non-primary-sponsor opportunities

Include only actionable opportunities or watch items with a concrete reason to remain visible.

For each, capture:

- status
- deadline
- award scale when decision-relevant
- scientific fit
- strategic value/limitation
- collaborator decision gate, if any
- next action

Avoid maintaining a generic catalog of possible foundations.

## 5. Portfolio calendar

Include actual pending applications and concrete future targets. Do not fill empty cycles merely because they exist.

Suggested columns:

| Date | Opportunity | Type | Program | Status |

Later uncommitted capacity can be summarized in prose.

## 6. Repository structure

Optional. Keep only if the portfolio also functions as a repository operating document.

## 7. Opportunity tracking schema

Useful fields:

- sponsor
- mechanism/opportunity number
- project/program
- A0/A1 or equivalent
- deadline/internal deadline
- status
- award/project period
- eligibility
- PI/multi-PI role
- collaborators
- scientific overlap check
- preliminary-data requirement
- dependencies
- last verified date
- next action

## 8. Immediate action queue

List only unresolved current actions. Remove completed development history.

Order by consequence and deadline, not by when an item was first added.

## 9. Guiding principle

End with a short statement that submission volume serves a coherent, diversified, independently fundable research program rather than becoming the objective itself.
